# جامع مدرسہ مینجمنٹ سسٹم

مدرسہ سیدہ عائشہ صدیقہ رضی اللہ عنہا للبنات — شادی لارج، ضلع بدین، سندھ، پاکستان

## مرحلہ 2: Next.js + TypeScript کی بنیاد

مین ڈیش بورڈ (مرحلہ 1 میں منظور شدہ ڈیزائن) اب Next.js اور TypeScript پر منتقل کر دیا
گیا ہے۔ ڈیزائن، رنگ، اردو فونٹ، RTL ترتیب اور تمام 27 شعبوں کے بٹن ویسے ہی ہیں جیسے
منظور ہوئے تھے — اس مرحلے میں ڈیزائن میں کوئی تبدیلی نہیں کی گئی۔

- مکمل اردو RTL انٹرفیس
- مین ڈیش بورڈ: 4 اعدادوشمار (ابھی صفر / خالی، کوئی فرضی ڈیٹا نہیں) اور 27 شعبوں کے بٹن
- ہر شعبے کا اپنا الگ صفحہ ہے (مثلاً ‎/departments/students) — فی الحال ہر صفحے پر صرف
  «زیرِ تعمیر» حالت اور ڈیش بورڈ پر واپس آنے کا بٹن ہے
- اندرونی نظام (طلبہ، اساتذہ، فیس، حاضری، مالیات) اگلے مرحلوں میں، منظوری کے بعد بنے گا

لائیو ڈیش بورڈ: https://madrasa-management-system-madrsa.vercel.app

## مرحلہ 3: ڈیٹا بیس + محفوظ لاگ اِن کی بنیاد (جاری)

Supabase (مفت درجہ) سے ڈیٹا بیس اور لاگ اِن کی بنیاد بنائی جا رہی ہے، تاکہ اگلے
مرحلوں میں شعبے اصل ریکارڈ محفوظ کر سکیں۔

- Supabase پروجیکٹ: PostgreSQL + Auth (لاگ اِن) + Row Level Security
- میزیں: `madrasas`، `profiles`، `audit_log` — ہر ریکارڈ کے ساتھ اس کے مدرسے کی شناخت
- RLS پالیسیاں: ہر صارف صرف اپنے مدرسے کا ڈیٹا دیکھ سکے
- لاگ اِن صفحہ: اردو RTL، ای میل + پاس ورڈ (`/login`)
- خفیہ `service_role` چابی کبھی استعمال نہیں ہوتی — صرف عوامی (publishable) چابی

## فائلوں کی ترتیب

```text
package.json                  — Next.js، React اور TypeScript (سب مفت / اوپن سورس)
tsconfig.json                 — TypeScript کی ترتیبات
next.config.ts                — Next.js کی ترتیبات
src/
  app/
    layout.tsx                — بنیادی ڈھانچہ (اردو، RTL، عنوان، اردو فونٹ)
    page.tsx                  — مین ڈیش بورڈ
    globals.css               — مرحلہ 1 کی منظور شدہ CSS جوں کی توں
    departments/[slug]/page.tsx — ہر شعبے کا الگ صفحہ (27 صفحے)
    profile/page.tsx          — «میرا پروفائل» کا صفحہ
    login/page.tsx            — لاگ اِن صفحہ (مرحلہ 3، اردو RTL)
  middleware.ts               — ہر درخواست پر Supabase سیشن تازہ رکھتا ہے
  components/
    TopBar.tsx                — اوپر کی سرخی (لوگو، نام، تاریخ، اطلاعات، صارف مینو)
    StatsRow.tsx              — چار اعدادوشمار (صفر / خالی)
    DepartmentGroups.tsx      — شعبہ جات کے گروپ اور بٹن
    ModuleCard.tsx            — شعبے کا «زیرِ تعمیر» کارڈ اور واپس جانے کا بٹن
    icons.tsx                 — تمام SVG آئیکون (اصل فائل جیسے)
  data/
    departments.ts            — 27 شعبوں اور 4 اعدادوشمار کی تعریفیں (ڈیٹا، کوڈ سے الگ)
  lib/
    types.ts                  — بنیادی اقسام (شعبہ، گروپ، اعدادوشمار)
    tenancy.ts                — مستقبل کے Multi-Tenant اور Multi-User نظام کی بنیاد
                              (صرف اقسام اور اصول — کوئی ڈیٹا بیس یا لاگ اِن نہیں)
    supabase/                 — Supabase کلائنٹ (براؤزر، سرور، middleware) — مرحلہ 3
supabase/
  migrations/001_stage3_foundation.sql — میزیں + RLS پالیسیاں (مرحلہ 3)
.env.example                  — Supabase کی ترتیبات کی مثال (اصل قدریں .env.local میں)
```

## مرحلہ 4 — ڈیش بورڈ بند + طلبہ کا ریکارڈ (9 نومبر 2026)

صارف کی منظوری سے دو کام:

**4A — ڈیش بورڈ لاگ اِن کے پیچھے بند:**
- لاگ اِن کے بغیر ہر صفحہ `/login` پر بھیج دیا جاتا ہے (middleware)۔
- لاگ اِن صفحے سے «واپس ڈیش بورڈ» کا لنک ہٹا دیا گیا (اب وہیں لوٹتا تھا)۔
- صارف کے مینو میں «لاگ آؤٹ» شامل کیا گیا۔

**4B — طلبہ کا ریکارڈ (پہلا مکمل ماڈیول):**
- میز `students` (`supabase/migrations/002_stage4_students.sql`) + RLS —
  ہر صارف صرف اپنے مدرسے کی طالبات دیکھ/لکھ سکتا ہے۔ DELETE کی کوئی پالیسی
  نہیں: ریکارڈ کبھی حذف نہیں ہوتا، صرف status = `withdrawn` (خارج) ہوتا ہے۔
- صفحات: `/departments/students` (فہرست)، `/departments/students/new`
  (نیا فارم)، `/departments/students/[id]` (تفصیل + تبدیلی)۔
- کھیت: نام، والد کا نام، سرپرست، فون، تاریخِ پیدائش، شعبہ (حفظ / ناظرہ /
  درسِ نظامی)، جماعت، داخلہ تاریخ، پتہ، حالت۔ رجسٹریشن نمبر خودکار ہے
  (اپنے مدرسے کی گنتی + 1، چار ہندسوں میں)۔
- ڈیش بورڈ کا «کل طلبہ» کارڈ اب اصل تعداد دکھاتا ہے (صرف فعال طالبات)۔
- ہر اضافہ/تبدیلی `audit_log` میں درج ہوتی ہے (کون، کب، کیا)۔

**اس مرحلے میں کیا نہیں ہے:**
- حاضری، فیس، امتحانات، اساتذہ — یہ اگلے الگ مراحل ہیں۔
- کوئی فرضی ڈیٹا شامل نہیں کیا گیا۔
- Migration 002 پہلے Supabase SQL Editor میں چلانی ہے، پھر پہلی طالبہ
  شامل کر کے اصل جانچ ہوگی۔
